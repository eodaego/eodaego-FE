# 소셜 로그인 및 약관 동의 연동

> **PR**: [eodaego-FE#14](https://github.com/eodaego/eodaego-FE/pull/14) — `20260712_#13_소셜_로그인_및_약관_동의_연동` → `main`
> 99개 파일, +4631/−2311, 커밋 12개

### 📌 작업 개요

`lib/features/auth/`와 `lib/features/user/`의 데이터 계층은 이전 프로젝트(cops_and_robbers)에서 이식된 상태였다. 구조는 완성돼 있었지만 **API 계약이 어대GO 백엔드와 전부 어긋나** 로그인 시 404가 발생했다.

이번 작업으로 계약을 정본(`docs/api-docs.json`)에 맞추고, **소셜 로그인 → 약관 동의 → 닉네임 설정 → 홈 진입**까지 온보딩 전 구간을 실서버와 연결했다.

---

### 🎯 구현 목표

1. Google/Apple 로그인이 실서버와 왕복하고 토큰이 저장된다
2. 약관 동의 조회·제출이 정본 계약과 일치한다
3. 닉네임 설정이 **서버에 영속**된다 (기존에는 로컬 상태만 바꾸고 사라졌다)
4. 앱 재시작 후 로그인이 유지되며, 불완전한 로컬 상태에서는 **fail-closed**로 동작한다
5. 토큰 자동 재발급이 정상 동작한다

### ✅ 구현 내용

#### 1. API 경로 버전 적용

- **파일**: `lib/core/constants/api_endpoints.dart`
- **변경**: private `_v1 = '/api/1'` 상수를 두고 모든 경로를 문자열 보간으로 조립
- **이유**: `@Path('version')` 파라미터 방식은 호출부마다 `'1'`을 들고 다녀야 하고, Dio `baseUrl`에 넣으면 서버 주소와 API 버전이 한 문자열에 섞인다. `const` 문자열 보간은 컴파일 타임 상수라 Retrofit 어노테이션에서 그대로 쓸 수 있다

#### 2. 공통 에러 응답 포맷 교체

- **파일**: `lib/core/network/api_error_response.dart`, `dio_exception_handler.dart`
- **변경**: RFC 7807(`title`/`status`/`detail`/`instance`) → `errorCode`/`errorMessage`/`fieldErrors`
- **이유**: 분기 로직은 `e.response?.statusCode`를 쓰므로 영향 없음. `fieldErrors`는 400 검증 실패 디버깅용으로 로그에만 사용

#### 3. 로그인 계약 정합

- **파일**: `login_request_model.dart`, `login_response_model.dart`, `auth_repository_impl.dart`, `auth_result_entity.dart`, `secure_token_storage.dart`
- **변경**: flat 응답 파싱, `userId` UUID 전환, `logout` 요청 바디 제거, 호출자 없는 reissue DTO 삭제

**`fcmToken` 생략이 기능 요구사항**이다. `@JsonSerializable(includeIfNull: false)`로 `null`일 때 JSON에서 키 자체를 뺀다. 서버는 값이 있을 때만 갱신하므로, 빈 문자열을 보내면 FCM을 받을 수 없는 환경(에뮬레이터 등)에서 로그인할 때마다 **서버에 저장된 멀쩡한 토큰을 덮어쓴다.**

#### 4. 약관 동의 API

- **파일**: `agreement_request_model.dart`, `agreement_response_model.dart`, `user_remote_datasource.dart`, `user_repository_impl.dart`
- **변경**: `PUT` → `PATCH`, 요청/응답 필드명 4종 교체
- **이유**: 신규 회원은 항상 `requiresAgreement: true`로 내려오고 라우터가 약관 화면을 강제하므로, 이 API가 깨져 있으면 **신규 회원이 홈에 도달할 수 없다**

Domain Entity(`AgreementStatusEntity`)의 필드명은 **유지**했다. 화면·Provider·테스트가 이 이름을 쓰며, Domain 이름은 wire 계약과 독립이다.

#### 5. 닉네임 설정 서버 연동

- **파일**: `validators.dart`(신규), `nickname_response_model.dart`(신규), `auth_provider.dart`, `nickname_setup_page.dart`
- **변경**: `AuthNotifier.updateNickname`이 서버 저장 성공 후에만 상태를 갱신

기존에는 `updateNicknameCompleted()`가 로컬 상태만 바꿔 **사용자가 정한 닉네임이 서버에 남지 않았다.** 다음 로그인 응답의 서버 닉네임으로 덮어써졌다.

서버가 값을 정규화할 수 있으므로 입력값이 아니라 **응답값**을 상태에 반영한다. 실패 시 상태를 바꾸지 않고 예외를 화면으로 올려 재시도할 수 있게 한다.

사전 중복확인 API가 정본에 없어 관련 코드를 삭제하고, 제출 시 **409 `NICKNAME_ALREADY_EXISTS`**로 판별한다.

#### 6. 앱 재시작 시 로그인 복원 (fail-closed)

- **파일**: `auth_provider.dart`의 `AuthNotifier.build()`, `secure_token_storage.dart`

기존 `build()`는 `getMyProfile()`을 호출했는데 **정본에 해당 API가 없다**(`GET /api/1/members/me`는 존재하지 않음). 로그인 응답의 `nickname`/`requiresAgreement`를 로컬에 저장하고 그 값으로 복원하도록 바꿨다.

**핵심은 `getRequiresAgreement()`가 `Future<bool?>`이라는 점이다.** 로컬 저장은 여러 개의 독립적인 비동기 쓰기라, 중간에 앱이 종료되면 불완전한 스냅샷이 남을 수 있다. 누락된 값을 `false`로 읽으면 **약관 게이트를 우회**하므로, `userId` 또는 `requiresAgreement`가 하나라도 없으면 세션을 정리하고 재로그인을 유도한다.

#### 7. 토큰 자동 재발급 수정

- **파일**: `lib/core/network/auth_interceptor.dart`
- **변경**: `_parseTokens`를 flat 구조로 수정, 도달 불가능한 분기 제거, `errorCode` 매핑을 실제 실패 경로로 이동

재발급 응답이 flat인데 중첩 `tokens`를 찾고 있어 **파싱에 실패해 강제 로그아웃되던 상태**였다.

`onError`의 reissue 분기는 **도달할 수 없는 죽은 코드**였다. 재발급은 인터셉터 없는 `_plainDio`로만 호출되고, `AuthRemoteDataSource.reissue()`는 호출자가 0건이었다. 실제 실패 경로(`catch`)에서 `errorCode`를 읽도록 옮겼다.

일시 실패(네트워크 단절·타임아웃·5xx)에서는 토큰을 지우지 않고 명시적 거부(400/401/403)에서만 정리하는 기존 정책은 그대로 유지했다.

#### 8. 온보딩 흐름 이탈 수정

- **파일**: `lib/router/app_router.dart`

라우터에 `/agreement → /home` 탈출 규칙은 있는데 **`/nickname-setup → /home`이 없었다.** 닉네임 저장이 성공해 `isNewUser=false`가 되면 모든 분기를 빠져나가 `return null` — 사용자가 그 화면에 갇혔다. 앱을 강제 종료해야만 홈에 갈 수 있었다.

한 줄(`if (path == RoutePaths.nicknameSetup) return RoutePaths.home;`)과 회귀 테스트 4종으로 수정했다.

#### 9. 인증 비밀값 로그 노출 제거

- **파일**: `firebase_auth_datasource.dart`, `auth_interceptor.dart`, `dio_client.dart`

디버그 빌드에서 Firebase ID Token 전문, 재발급 응답 본문(새 accessToken + refreshToken), 모든 요청의 `Authorization` 헤더가 콘솔에 찍히고 있었다. 세 곳 모두 제거했다.

`LogInterceptor`의 `requestBody`/`responseBody`는 **유지**했다. 이번 작업의 핵심이 요청·응답 스키마 정합이라 본문 확인이 디버깅에 필수이고, `Authorization` 헤더가 모든 요청에 실려 노출 빈도가 압도적으로 높아 그쪽 차단 이득이 크다.

#### 10. 약관 동의 화면 개편

- **파일**: `agreement_page.dart`, `assets/legals/marketing_consent.json`(신규)
- **변경**: 전체 동의 행 + 개별 약관 4종 목록, 각 행의 `>` 탭으로 전문 열기

#### 11. 화면·문구 정리

- 닉네임 화면 레이아웃을 약관 화면과 통일 (입력 가운데 정렬, 완료 버튼 하단, 여백 동일)
- 로그인 에러 처리를 단일 경로로 정리 — 사용자가 할 수 있는 행동이 재시도뿐이라 코드별 분기를 없애고, 사용처를 잃은 `firebase_auth_error_handler.dart`(156줄) 삭제

### 🔧 주요 변경사항 상세

#### 정본에 `required` 선언이 없는 문제

`LoginResponse`, `ReissueResponse`, `ErrorResponse`에는 OpenAPI `required` 배열이 **없다**(`LoginRequest`에는 있다). 문자 그대로 따르면 모든 응답 필드가 nullable이고, DTO를 전부 `required`로 두면 필드 누락 시 런타임 타입 오류가 난다.

**정본을 신뢰하는 쪽이 아니라 앱이 죽지 않는 쪽으로 설계했다:**

| 필드 | 처리 | 근거 |
|---|---|---|
| `accessToken`, `refreshToken`, `userId` | `required` 유지 | 없으면 세션이 성립하지 않는다. 조용히 넘어가는 것보다 실패가 맞다 |
| `requiresAgreement` | `@Default(true)` | **fail-closed** — 누락 시 약관 게이트를 열지 않는다 |
| `firstLogin` | `@Default(false)` | 누락 시 기존 회원으로 취급 |
| `nickname` | `@Default('')` | 표시용, 흐름에 영향 없음 |

필수 3개가 누락된 응답은 `fromJson`이 던지고, Repository의 기존 `catch` 폴백이 이를 `AuthException`으로 변환해 로그인 화면에 안내를 띄운다. 앱은 죽지 않는다.

#### 닉네임 온보딩은 강제 게이트가 아니다

`firstLogin`은 "이번 요청에서 가입됨"이지 "닉네임 설정을 마쳤는가"가 아니다. 설정을 완료하지 않은 채 로그아웃·재설치하면 다음 로그인은 `firstLogin=false`가 되어 설정 화면이 다시 열리지 않는다.

**이것을 의도된 동작으로 확정했다.** 서버가 이미 닉네임을 발급해 뒀으므로 사용자는 자동 발급 닉네임으로 앱을 정상 사용하고, 설정 페이지에서 언제든 바꾼다. 닉네임 설정은 1회성 편의 온보딩이다.

전제는 설정 페이지의 닉네임 변경이 제공된다는 것이다. 그 전까지는 자동 발급 닉네임을 바꿀 수단이 없다.

### 📌 참고사항

#### 릴리스 시 공지 필요

**기존 설치 사용자는 이번 업데이트 후 한 번 재로그인해야 한다.** 이전 버전에는 `requires_agreement` 키가 없으므로 fail-closed cold start가 이를 불완전한 세션으로 판정해 토큰을 정리한다. 설계대로의 동작이지만 사용자에게는 갑작스러운 로그아웃으로 보이므로 패치노트에 명시한다.

`userId`의 `int → String` 전환은 안전하다. `flutter_secure_storage`는 이미 문자열로 저장했고 기존 값은 그대로 읽힌다. `userId`는 서버로 다시 전송되지 않는다.

#### 후속 작업

1. **설정 페이지 (닉네임 변경 + 회원탈퇴)** — 온보딩을 건너뛴 사용자가 닉네임을 바꿀 유일한 수단이라 우선순위가 높다. Repository와 Validator가 준비돼 있어 닉네임은 화면만 붙이면 된다. 회원탈퇴는 경로가 맞춰져 있고, `DeleteAccountResponseModel`을 걷어내 204(본문 없음)에 맞추는 작업이 남아 있다
2. **백엔드 요청** — `LoginResponse` / `ReissueResponse` / `ErrorResponse`의 OpenAPI `required` 선언 보완
3. **cold start에서 `getAgreements()` 복원** — 경로가 정상화됐으므로 다시 연결하면 서버 기준 약관 상태를 반영할 수 있다
4. **`getMyPage` 계열 죽은 코드 정리** — `GET /api/1/members/me`는 정본에 없어 호출 시 404다
5. **Riverpod dispose 순서 하드닝** — `ProviderContainer.dispose()`가 `_disposed` 플래그를 개별 element dispose보다 먼저 세워, `AuthNotifier`의 `ref.onDispose` 콜백이 그 시점에 `ref.read`를 호출하면 예외가 난다. 루트 컨테이너는 앱 실행 중 dispose되지 않아 현재는 발생하지 않지만, 스코프드 컨테이너를 도입하면 터진다
6. **`analysis_options.yaml`에 `**/*.g.dart` exclude 추가** — 생성 코드의 lint가 그대로 노출된다
