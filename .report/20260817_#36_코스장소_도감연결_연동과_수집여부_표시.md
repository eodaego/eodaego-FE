# 코스 장소 도감 연결 정보 연동과 수집 여부 표시

### 📌 작업 개요

코스 장소와 도감을 잇던 **이름 검색 조인을 걷어내고**, 백엔드가 새로 내려주는 `catalogItemId`·`collected` 두 필드로 갈아탐. 지도 마커 카드의 세 얼굴은 그대로 두고 판정 근거만 교체.

덤으로 얻은 것이 더 크다. 조인이 사라지면서 **지도 마커와 코스 목록에 수집 체크를 붙일 수 있게 됐다.** 예전 구조로는 화면을 열자마자 장소 수만큼 도감을 조회해야 해서 붙일 수 없던 표시다.

### 🔍 문제 분석

기존에는 코스 응답에 도감 연결 정보가 없어, 장소 이름으로 도감 목록을 검색해 이어 붙였다.

| 항목 | 기존 | 이번 |
|---|---|---|
| 도감 연결 근거 | 이름 검색 + 카테고리 필터 + 이름 완전 일치 재검증 | 응답의 `catalogItemId` 하나 |
| 오연결 위험 | 서버 검색이 부분 일치 — "식물원"이 "식물원 카페테리아"까지 물어옴 | 없음. ID 매칭 |
| 카드 완성 시점 | 마커를 누를 때마다 도감 조회 1회, 응답이 와야 카드 완성 | ②·③은 첫 프레임에 완성, ①만 상세 1회 |
| 마커·목록 수집 표시 | 불가 — 화면 열자마자 장소 수만큼 호출해야 함 | 응답에 이미 들어와 있어 즉시 표시 |

이름 조인은 도감 항목이 늘수록 접두사 충돌 확률도 함께 오르는 구조였다.

- 코스 장소 DTO·엔티티에 도감 항목 ID와 수집 여부 추가, 이름 조인 제거
- 카드가 보여주는 세 상태는 유지하고 판정 근거만 교체
- 수집한 장소만 도감 상세를 부르게 해 왕복 줄이기 (미수집 상세는 서버가 403으로 막음)

### 🔧 주요 변경사항 상세

#### 카드의 세 얼굴 — 별도 상태 타입 없이 두 필드로

| `collected` | `catalogItemId` | 카드 | 서버 왕복 |
|---|---|---|---|
| true | 있음 | ① 이미 수집함 — 사진·도감 코드·"도감에서 보기" | 상세 1회 |
| false | 있음 | ② 아직 못 모음 — `?` 썸네일·"여기서 찍기" | **없음** |
| false | null | ③ 도감에 없는 시설 — 이름 밑 한 줄만 | 없음 |

**특이사항**:
- 예전 `PlaceCatalogStatus` 튜플 타입을 되살리지 않았다. 두 필드로 세 갈래가 그대로 나오므로 중간 타입이 필요 없음
- ①도 칩과 버튼은 먼저 그려 둔다. 상세 도착을 기다렸다 그리면 카드 높이가 튀어 지도를 가리는 면적이 출렁임
- 도감 코드 자리는 도착 전에 빈 줄로 둔다. `-`를 깔면 코드가 도착하는 순간 글자가 갈아끼워지는 게 보임
- "도감에서 보기"는 이제 `extra` 없이 ID만 넘긴다. 방금 부른 상세가 캐시에 올라가 있어 상세 화면이 다시 조회하지 않음
- `map_page.dart`의 `KeyedSubtree`(장소가 바뀔 때 도감 조회를 새로 돌리려던 장치)는 근거가 사라져 제거

#### 마커 뱃지 디자인 — 색은 손대지 않는다

카테고리색은 그대로 두고 **이미 만난 곳에만** 체크를 얹는다.

**특이사항**:
- 미수집을 무채색으로 흐리는 방식은 쓰지 않았다. 도감 목록에서는 빈칸이 채우고 싶게 만들지만, 지도에서는 가야 할 곳이 흐려져 신호가 반대로 읽힘. 색이 살아 있는 마커 = "아직 만날 수 있는 곳"
- 뱃지를 흰 원 + 진한 체크로 먼저 그렸다가, **카테고리 `dark` 채움 + 흰 체크 + 흰 링**으로 바꿈. 마커 자체가 흰 링을 두르고 있어 첫 안은 경계가 사라지고 순서 숫자와 뭉쳐 보였음
- 뱃지는 원 바깥으로 밀어 숫자를 가리지 않게 하되(`Positioned` 음수 오프셋), `SizedBox` 크기는 마커 원 그대로 둬서 목록·카드 정렬이 흔들리지 않게 함
- Canvas 쪽도 같은 규칙(흰 테두리 → `dark` 채움 → 흰 체크)을 손으로 그림. 두 경로가 같은 그림이 되도록 반경·오프셋을 맞춤

#### 수집 후 코스 동기화 — 같은 인스턴스를 돌려주는 이유

`markCollected`는 **바뀔 장소가 없으면 자기 자신을 그대로 돌려준다.**

**특이사항**:
- `park_google_map.dart`의 `didUpdateWidget`이 `oldWidget.course != widget.course`로 마커 비트맵 재생성을 결정하는데, `CourseEntity`는 `==`를 재정의하지 않아 사실상 인스턴스 동일성 검사다. 새 인스턴스를 만들면 코스와 무관한 도감을 모을 때마다 마커 PNG를 전부 다시 굽게 됨
- 퀴즈로 모은 도감이 지금 보는 코스와 무관한 경우가 대부분이라 헛돌면 안 되는 자리
- 도감 feature가 코스 타입을 이름으로 쓰지 않도록 `selectedCourseProvider`(core)만 참조. feature 간 직접 import 규칙 유지

#### 목 좌표는 실제 위치가 아니다

`park_map_data.dart`의 정규화 도식 좌표(`map_v6.jpg` 기준 offset)를 공원 위경도 범위에 선형 매핑해 만든 값이다.

**특이사항**:
- 도식 이미지는 회화적 일러스트라 실제 지형의 아핀 변환이 아니다. 같은 변환을 실제 위경도를 아는 출입문 11곳에 대입해 검증하면 **최대 381m(능동문), 중앙값 221m, 최소 104m(정문)** 벌어진다. **목 픽스처 수준의 근사치일 뿐 실제 위치가 아님** — 마커가 실제와 다른 길 건너편에 찍힐 수 있다
- 실제 API 모드에서는 서버가 준 좌표를 그대로 쓰므로 영향 없음
- 이 값을 다른 용도로 재사용하지 말 것

### 📌 참고사항

- **코스 추천 결과 카드의 순서 번호 원에는 체크가 붙지 않는다.** `lib/core/widgets/course_card.dart`의 `_NumberDot`은 `MapMarker`와 별개 위젯이라 이번 배선에서 빠짐. 필요하면 후속으로 통일 검토
- **즐겨찾기 하트를 누르면 마커 PNG가 전부 다시 구워진다.** `copyWith(favorite:)`가 새 `CourseEntity`를 만들고 `didUpdateWidget`의 인스턴스 검사에 걸리기 때문. 기존 동작이며 이번 범위 밖
- **`lib/core/config/env_config.dart`의 주석이 사실과 다르다.** "퀴즈·코스·즐겨찾기는 플래그와 무관하다"고 적혀 있지만 `courseRemoteDataSourceProvider`는 실제로 `useMockData`를 탄다(목 데이터소스로 갈아탐). 이번 작업에서는 손대지 않음
- 목 픽스처 좌표는 실제 위치가 아니다(위 상세 참조)
- 시설 API가 붙으면 출입문 11곳·고객안내센터를 포함한 시설 전체와 운영시간을 지도에 얹을 수 있다. 별도 이슈로 다루는 편이 적절함
