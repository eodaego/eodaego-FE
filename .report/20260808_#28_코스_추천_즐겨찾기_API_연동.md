# 코스 추천·즐겨찾기 API 연동과 추천 조건 화면 개편

### 📌 작업 개요

코스 추천·즐겨찾기·지도·홈 프리뷰가 공유하던 하드코딩 목 코스 6개를 실제 백엔드 API로 교체. 코스 기능에 data/domain 계층이 아예 없던 상태에서 4계층을 새로 구축.

단순 배선이 아니라 **추천 조건 화면을 전면 개편**해야 했다. 화면이 묻는 조건과 서버가 받는 조건이 어긋나 있었기 때문.

### 🔍 문제 분석

기존 화면과 서버 스펙의 불일치:

| 항목 | 기존 화면 | 서버 스펙 |
|---|---|---|
| 출입문 | 입구만, 3개(정문·후문·구의문), 건너뛰기 가능 | 입구·출구 **둘 다 필수**, 11개 |
| 관심분야 | 3개 중 **단일 선택** (동물·식물·장소) | 7개 **복수 선택** |
| 동행 유형 | 없음 | 5개 |
| 추천 방식 | 로컬 리스트를 조건으로 필터링 | AI 서버가 코스를 새로 생성 |
| 즐겨찾기 | 화면 로컬 `setState`, 재진입 시 초기화 | 서버 저장, 서버 정렬 |

### 🎯 구현 목표

- 코스 추천·즐겨찾기 API 연동 (Clean Architecture 4계층)
- 추천 조건 화면 3단계 → 5단계 개편
- 즐겨찾기를 서버 상태로 전환
- 목 모드에서도 동작 유지

### 🔧 주요 변경사항 상세

#### 추천 조건 5단계 구성

| 단계 | 질문 | 입력 | 건너뛰기 |
|---|---|---|---|
| 1 | 어느 문으로 들어왔어? | 출입문 11개 칩 그리드 | **불가** |
| 2 | 어느 문으로 나갈까? | 출입문 11개 칩 그리드 | **불가** |
| 3 | 얼마나 놀다 갈까? | 1시간/2시간/반나절 | 가능 |
| 4 | 뭐가 제일 좋아? | 관심분야 7개 복수 선택 | 가능 |
| 5 | 누구랑 왔어? | 동행 유형 5개 | 가능 |
| 6 | 결과 | 코스 카드 스와이프 | — |

**특이사항**:
- 출입문 11개는 기존 카드 UI(이모지+제목+부제)로는 스크롤이 너무 길어져 `CategoryChip` 그리드로 전환. 새 위젯을 만들지 않고 기존 칩 재사용
- 스텝 4는 복수 선택이라 자동 넘김 대신 버튼으로 확정. 아무것도 안 고르면 라벨이 "건너뛰기", 하나 이상 고르면 "다음"으로 바뀜. 버튼을 둘로 나누면 같은 동작이 달라 보임
- 스텝 1·2에서 "건너뛰면 전체에서 골라 추천해요" 안내 문구 제거 (거짓말이 됨)
- 체류시간 선택은 60/120/240분으로 변환해 전송

#### 추천 API 호출 시점

마지막 조건 단계에서 선택 또는 건너뛰기를 하면 **그때 1회만** 호출.

**특이사항**:
- 기존에는 조건을 바꿀 때마다 로컬 리스트가 즉시 걸러졌다. 이제 한 번이 AI 서버 호출이고, **호출할 때마다 서버에 코스가 새로 저장된다**
- 결과를 provider가 보관하므로 카드 스와이프·리빌드로 재호출되지 않음
- 조건을 바꾸러 뒤로 갔다 다시 오면 재호출 (조건이 바뀌었을 수 있으므로)

#### AI 서버 장애와 결과 0개 구분

| 상황 | 문구 | 버튼 |
|---|---|---|
| 503 (`errorCourseAiUnavailable`) | 지금은 코스를 만들지 못했어요 / 잠시 후 다시 시도해 주세요 | 다시 시도 |
| 결과 0개 | 조건을 바꾸면 코스를 찾을 수 있어요 | 조건 다시 고르기 |

**특이사항**:
- 서버 장애를 조건 문제로 오해하면 사용자가 조건만 계속 바꾸며 헛수고함
- Repository에서 `statusCode == 503`을 잡아 전용 `messageKey`를 단 `ServerException`으로 던지고, 화면이 그 키로 분기
- 응답 코스 개수는 AI가 정하며 고정 개수를 보장하지 않음. 화면은 개수에 무관하게 동작

#### 즐겨찾기 낙관적 토글

하트를 누르면 화면이 먼저 반영하고, 서버가 실패하면 되돌린 뒤 안내.

**특이사항**:
- 등록(POST)·삭제(DELETE) 둘 다 서버가 멱등 처리하므로 더블탭·재시도가 안전
- 별도 공유 상태 계층을 두지 않음. 두 화면이 각자 자기 목록을 낙관적으로 갱신하고, 성공 시 `favoriteCoursesProvider` 무효화로 서버 진실에 다시 맞춤
- 추천 결과의 `favorite`는 문서상 항상 `false` (방금 만든 코스라서). 초기 상태는 늘 빈 하트

#### 즐겨찾기 정렬 서버화

기존 칩 + 방향 토글이 서버 `sort` 4값에 정확히 대응해 UI는 거의 그대로 유지.

| 칩 상태 | sort |
|---|---|
| 최근에 저장한 순 ↓ (초기) | `LATEST` |
| 최근에 저장한 순 ↑ | `OLDEST` |
| 걸리는 시간 순 ↓ | `DURATION_LONG` |
| 걸리는 시간 순 ↑ | `DURATION_SHORT` |

**특이사항**:
- "전체" 칩만 제거. 대응하는 서버 값이 없고 기본값이 `LATEST`라 최근순↓이 초기 선택
- 로컬 정렬 로직 전량 삭제

#### 코스 카드 뱃지 규칙

서버 `interestTypes`는 7종이라 디자인 시스템의 3색(동물·식물·장소)과 맞지 않는다. **장소 카테고리 최빈값**으로 카드 색을 정함.

**특이사항**:
- 동률이면 방문 순서가 빠른 쪽. 코스의 첫인상을 색으로 씀
- `tagLabels`가 2~3개여도 카드 상단 한 줄에 뱃지 3개는 안 들어가므로 첫 번째만 사용. 빈 배열이면 카테고리 이름으로 폴백
- 입구 라벨 대신 "정문 → 남문" 형태로 입출구 함께 표시

#### 게스트 처리

즐겨찾기 화면에서 게스트는 **API 호출 자체를 하지 않고** 빈 상태를 그림.

**특이사항**:
- 게스트는 토큰이 없어 401이 나고, 인터셉터가 세션 만료로 오인해 로그인한 적 없는 사용자를 강제 로그아웃시킴. 홈 도감 요약이 겪었던 버그와 같은 경로

### 📌 참고사항

- **출입문 11개 한글 라벨이 잠정값**이다. 서버 enum 이름에서 직역했으며, 특히 `HOEGWAN_GATE`(회관문)·`EAST_GATE_1/2`(동문1/2)·`NORTH_GATE_1/2`(북문1/2)의 실제 공원 안내도 표기를 확인해 확정해야 함. 코드에도 주석으로 표시
- **추천 호출마다 서버에 코스가 새로 저장된다.** 사용자가 조건을 바꿔가며 여러 번 시도하면 저장이 계속 쌓이는데, 정리 정책이 있는지 백엔드 확인 필요
- 선택한 코스는 메모리에만 유지. 앱을 다시 켜면 초기화됨 (기존 동작과 동일)
- 목 모드 시각 확인 필요: 5단계 진행, 문 11개 칩 그리드, 하트 토글, 정렬칩 방향 토글
