# 코스 추천 화면 정비 — 아이콘 격자·하단 고정 버튼·타임아웃 제거

### 📌 작업 개요

코스 추천 위저드(조건 5스텝 + 결과)의 선택지를 이모지 나열에서 아이콘 격자로 바꾸고, 스텝마다 달랐던 하단 버튼을 스크롤 밖 풀폭 고정 버튼으로 통일.

화면 정비만으로는 끝나지 않았다. 실 API로 돌려 보니 **추천 요청이 항상 타임아웃으로 실패**했고, **즐겨찾기 하트가 예외로 터졌다**. 둘 다 이번 작업에서 함께 잡았다.

### 🔍 문제 분석

#### 1. 선택 화면 (이슈 본문)

| 항목 | 기존 | 문제 |
|---|---|---|
| 체류시간·동행 아이콘 | 이모지 8개를 `Text`로 렌더링 | 기기·OS별로 그림이 달라지고 앱 그림체와 겉돎 |
| 출입문 11개·관심분야 7개 | `Wrap` + `CategoryChip` 알약 나열 | 폭이 제각각이라 훑기 어렵고 터치 영역이 좁음 |
| 하단 버튼 | 스크롤 **안**, 스텝마다 생김새가 다름 (`TextButton` / `width: 240` `AppButton`) | 위치가 흔들리고 화면을 내려야 보이는 경우 발생. 로그인 화면 풀폭 버튼과도 어긋남 |
| 자동 넘김 | `Future.delayed` 350ms를 취소 없이 예약 | 짧은 간격으로 다시 고르면 예약이 겹쳐 **두 스텝을 건너뜀** |

#### 2. 전역 타임아웃이 정상 요청을 끊음

코스 추천은 백엔드가 외부 AI 서버를 **동기로 호출**해 응답이 10초를 넘긴다. `DioClient`의 전역 `connectTimeout`/`receiveTimeout`/`sendTimeout` 10초가 서버 응답보다 먼저 끊어, 정상 요청이 `DioExceptionType.receiveTimeout`으로 실패했다.

#### 3. 즐겨찾기 토글이 응답 도중 폐기됨

`FavoriteToggle`이 autoDispose였다. 화면은 이 provider를 `ref.read(...notifier)`로만 쓰고 watch하지 않아, **API 응답을 기다리는 동안 구독자가 0이 되어 폐기**됐다. 폐기 시 Riverpod이 내부 `_futureCompleter`를 완료시키면서 비우지 않아, 응답이 돌아온 뒤 `state` 대입이 `Bad state: Future already completed`로 터졌다.

- 칩 나열 → 항목 수에 따라 열이 갈리는 격자
- 하단 버튼을 스크롤 밖 고정 + 스텝별 라벨·활성 규칙 통일
- 자동 넘김 예약 중복 제거
- AI 서버 대기 시간을 견디는 네트워크 설정과 대기 화면
- 즐겨찾기 토글 정상 동작

### 🔧 주요 변경사항 상세

#### 격자 구성 — 항목 수에 따라 열이 갈린다

| 스텝 | 항목 | 열 | `aspectRatio` | 타일 구성 |
|---|---|---|---|---|
| 입구·출구 | 11 | 3 | 2.0 | **라벨만** |
| 관심분야 | 7 | 3 | 1.3 | 아이콘 + 라벨 |
| 체류시간 | 3 | 2 | 1.85 | 아이콘 + 라벨 + 부제 |
| 동행 | 5 | 2 | 1.85 | 아이콘 + 라벨 + 부제 |

**특이사항**:
- **출입문에는 아이콘을 넣지 않았다.** 11개가 전부 '문'이라 같은 그림이 11번 반복되면 정보를 주지 못하고 노이즈만 늘어난다
- `aspectRatio`를 `OptionGrid`가 열 수로 추측하지 않고 **호출부가 명시**한다. 타일 구성이 같은 열 수 안에서도 갈리기 때문
- `GridView.count(shrinkWrap: true, physics: NeverScrollableScrollPhysics())`. 스텝 본문이 `SingleChildScrollView`라 격자가 스스로 스크롤하면 중첩된다. 최대 11개라 shrinkWrap 비용은 문제되지 않음
- 부제는 `maxLines: 1` + `ellipsis`. 두 줄로 늘면 타일 높이를 넘긴다

#### 하단 버튼 상태 규칙

| page | 스텝 | 미선택 | 선택됨 |
|---|---|---|---|
| 0 | 입구 (필수) | `다음` · **비활성** | `다음` |
| 1 | 출구 (필수) | `다음` · **비활성** | `다음` |
| 2 | 체류시간 | `건너뛰기` | `다음` |
| 3 | 관심분야 | `건너뛰기` | `다음` |
| 4 | 동행 (마지막) | `건너뛰기` | `코스 추천받기` |

**특이사항**:
- 자동 넘김(350ms)은 그대로 유지했다. 하단 버튼은 **자동 넘김을 대체하는 게 아니라 역할을 나눈다** — 지금 무엇이 골라졌는지 보여주는 상태 표시이자, 기다리지 않으려는 사람의 지름길
- 관심분야만 자동 넘김이 없다. 복수 선택이라 "다 골랐다"는 시점을 앱이 알 수 없어 버튼이 유일한 진행 수단
- 비활성은 `onPressed: null`로만 만든다 (디자인 시스템 규칙). 별도 disabled 플래그 없음
- 결과 스텝(5)에서는 `SizedBox.shrink()`. 코스 카드 안에 이미 CTA가 있어 버튼이 겹친다
- `AppButton` 기본 크기(353×56 = 393 − 20×2)를 그대로 써서 `width` 오버라이드 없이 로그인 화면과 같은 폭이 됨

#### 자동 넘김 취소 지점

```
_scheduleAdvance  → 예약 전에 이전 예약 cancel
_advanceFrom      → 진입 시 cancel (버튼을 먼저 눌렀을 때 예약이 한 번 더 넘기는 것 방지)
_goToResult       → 진입 시 cancel
선택 해제 (토글)   → cancel만 하고 재예약 안 함
dispose           → cancel
```

**특이사항**:
- 동행 스텝은 기존에 선택 즉시 `_goToResult()`를 호출했다. 다른 스텝과 같은 350ms 예약으로 맞춰 선택 피드백이 보이게 함
- 체류시간·동행은 같은 항목을 다시 누르면 선택이 풀린다. 이때 예약도 함께 걷어내야 선택을 푼 채로 넘어가지 않는다

#### 결과 화면을 가로 스와이프에서 세로 목록으로

`_ResultCards`가 내부 `PageView`(가로 스와이프) → `ListView.separated`(세로 스크롤).

**특이사항**:
- 코스 개수는 AI가 정하며 고정되지 않는다. 세로 목록이 개수에 무관하게 자연스럽고, 여러 코스를 비교하기도 쉽다
- **부작용이 하나 남았다** — 아래 「알려진 과제」 참조

#### 전역 타임아웃 제거의 남은 영향

세 값을 지우면서 확인한 것들:

| 항목 | 상태 |
|---|---|
| 토큰 재발급 전용 `plainDio` | ⚠️ **같은 `BaseOptions`를 공유**한다. 재발급 요청도 무기한 대기가 된다 |
| `DioExceptionHandler`의 타임아웃 분기 (`_isTimeoutError`) | 유지 — 개별 요청이 타임아웃을 걸면 그대로 동작 |

| 개별 요청의 `Options(receiveTimeout: ...)` | 여전히 유효 — 필요한 엔드포인트는 요청 단위로 걸면 된다 |

**특이사항**:
- `plainDio` 공유는 이번 변경으로 새로 생긴 노출이다. 재발급이 응답 없이 멈추면 그 요청도 함께 멈춘다. 요청 단위 타임아웃을 재발급 호출에 붙이는 방향으로 후속 검토 필요

### 📌 참고사항

- **전역 타임아웃이 사라졌다.** 앞으로 응답이 오지 않는 요청은 사용자가 화면을 벗어날 때까지 대기한다. 오래 걸리면 안 되는 엔드포인트는 요청 단위로 `Options(receiveTimeout: ...)`를 걸어야 한다
- 특히 **토큰 재발급이 `plainDio`로 같은 `BaseOptions`를 공유**한다. 재발급이 멈추면 그 요청도 함께 멈춘다는 점을 후속 작업에서 다룰 것
- 자동 넘김 350ms는 유지했다. 짧게 느껴지면 값만 바꾸면 되고, 예약 중복은 `Timer` 단일 보유로 이미 막혀 있다
