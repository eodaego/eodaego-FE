### 📌 작업 개요
앱에 노출되는 문구 약 150개를 전수 조사해 UX 라이팅 규칙 위반 21건을 교체했다. 해요체(규칙 1)와 캐주얼 경어(규칙 4)는 위반 0건이었고, 능동형(규칙 2)·긍정형(규칙 3)·한자어 풀어쓰기(규칙 5)에서만 위반이 나왔다. 화면마다 갈려 있던 같은 뜻의 문구도 한 가지로 통일했다.

### 🎯 구현 목표
- 부정형 문구를 긍정형으로 바꿔, 못 하는 일이 아니라 지금 할 수 있는 일을 알려준다
- 수동 표현을 능동형으로 바꾼다
- 한자어 명사를 풀어써 아이가 읽어도 뜻이 통하게 한다
- 같은 대상을 부르는 이름과 실패 안내 패턴을 하나로 통일한다
- 법정 문서 제목·서버 값·탭 이름처럼 바꾸면 안 되는 것은 손대지 않는다

### 🔧 주요 변경사항 상세

#### 도감 뱃지 어휘 통일
`collection_detail_page.dart`의 상태 뱃지를 `미수집`/`수집 완료` → `아직이에요`/`만났어요`로 바꾸면서, 같은 화면 아래쪽의 수집일 문구(`{날짜}에 만났어요`, 307행)와 어휘가 맞아떨어졌다. 도감 목록 그리드 타일(`collection_page.dart:285`)도 같은 `아직이에요`를 쓴다.

#### 실패 안내 패턴 결정
두 패턴 중 어느 쪽을 정본으로 삼을지가 이번 작업의 유일한 판단 지점이었다. `~하지 못했어요`는 형태상 부정형이지만, 규칙 3이 금지하는 것은 **혜택 대상 안내**의 부정형이다. 실제로 동작이 실패한 상황에서는 `문제가 생겼어요`보다 무엇을 못 했는지 명시하는 쪽이 정확하다고 보고, 다수(20곳)를 정본으로 확정했다.

**특이사항**:
- `favorite_page.dart`의 `걸리는 시간 순`은 띄어쓰기를 살렸다. `걸리는시간순`으로 붙이면 다시 명사 덩어리가 된다.

### 🚫 의도적으로 유지한 것

바꾸면 안 되거나, 규칙보다 다른 가치가 앞서는 문구는 그대로 뒀다.

| 대상 | 유지 이유 |
|---|---|
| `이용약관`, `개인정보처리방침`, `위치정보 이용약관`, `마케팅 정보 수신 동의` | 실제 법정 문서명이다. UI 라벨(`마케팅 정보 받기`)만 바꾸고 문서 제목은 원문 그대로 유지했다 |
| 실패 안내 `~하지 못했어요` 20곳 | 규칙 3의 부정형 금지는 혜택 대상 안내가 대상이다. 실제 실패에는 이 표현이 더 정확하다고 판단해 정본으로 확정 |
| 다이얼로그 왼쪽 버튼 `나중에` 3곳 | 규칙이 `취소`를 금지하는 이유는 "하던 작업이 취소된다"는 오해 때문이다. `나중에`에는 그 문제가 없고, 미루기라는 뜻을 `닫기`보다 정확히 전한다 |
| 탈퇴 경고 `되돌릴 수 없어요` (`my_page.dart:72`) | 파괴적 동작 경고는 캐주얼함보다 명확성이 앞선다 |
| 통계 라벨 `수집률`·`모은 도감` (`my_page.dart:352,360`) | 숫자 위에 붙는 라벨은 짧아야 읽힌다. 풀어쓰면 두 줄로 넘어간다 |
| 서버 enum 값 (`맑음`, `구름많음`, `없음` 등) | 서버가 내려주는 값이라 클라이언트가 바꿀 수 없다 |
| 탭·카테고리 이름, `debugPrint` 로그, 주석 | 사용자 노출 문구가 아니다 |

### 📌 참고사항

#### 실기기 확인이 필요한 지점
`collection_page.dart` 3열 그리드 타일의 `아직이에요`(5자)는 `tag13Bold` 기준 텍스트 폭 약 65px, 가용 폭 약 88px로 계산상 잘리지 않는다. 다만 폰트 렌더링 차이가 있을 수 있어 실기기 확인을 권한다. `maxLines: 1` + `TextOverflow.ellipsis`가 걸려 있어 넘치더라도 오류 없이 말줄임 처리된다.

#### 이번 조사로 확인된 것
- 해요체(규칙 1)와 캐주얼 경어(규칙 4)는 이미 전 화면에서 지켜지고 있다. `~시겠어요?`, `~께` 같은 과도한 경어는 한 건도 없었다
- 실패 안내 패턴이 `~하지 못했어요`로 정본화됐으므로, 앞으로 새 에러 문구는 이 패턴을 따르면 된다
