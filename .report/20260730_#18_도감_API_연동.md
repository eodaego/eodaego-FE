# 도감 API 연동 — 목록·상세·수집 현황 요약

> **이슈**: [#18](https://github.com/eodaego/eodaego-FE/issues/18) — `20260729_#18_도감_API_연동` → `main`
> 57개 파일, +5312/−502, 커밋 22개

### 📌 작업 개요

도감 목록·상세·홈 진행률 카드가 전부 `mockDogamItems` 80종 하드코딩 위에서 돌고 있었다. `lib/features/collection/`에는 `presentation/`만 있어 서버 데이터를 받을 통로 자체가 없는 상태였고, 이번 작업 비용의 대부분은 엔드포인트 3개 연동이 아니라 data·domain 계층 신설이었다.

`GET /catalog`(목록) · `GET /catalog/{id}`(상세) · `GET /catalog/summary`(요약) 세 엔드포인트를 붙이고 목업을 걷어냈다. `POST /catalog/{id}/collect`(수집)는 의도적으로 범위에서 뺐다.

---

### 🎯 구현 목표

1. 도감 목록·상세·홈 진행률 카드·마이페이지 통계 카드를 실서버 데이터로 교체
2. 카테고리 필터·이름 검색은 서버 재요청 없이 로컬에서 처리
3. 미수집 항목은 상세 화면에 진입은 되지만 상세 API를 호출하지 않음
4. 로딩·미수집·에러 세 상태가 시각적으로 구분됨 (shimmer 스켈레톤 vs 정적 `?` vs 재시도)

### 📌 범위 제외 — 수집(collect) API

앱에 사진 인식 기능이 없어 `catalogItemId`를 얻을 방법이 없다. 상세 화면에 수집 버튼을 두면 사용자가 탭만으로 371종을 전부 채울 수 있어 도감의 "발견하고 모은다"는 컨셉이 무너진다. 인식 API가 준비되면 별도 이슈로 진행한다.

화면 검증에는 백엔드 테스트 계정에 심어둔 샘플 수집 이력이 필요하다 — 앱에서는 수집이 늘어나지 않으므로, 수집 이력이 하나도 없으면 목록이 전부 미수집으로만 보여 상세·수집일·진행률을 확인할 길이 없다.

### 🔧 주요 변경사항 상세

#### 필터·검색은 로컬, 카운트 뱃지는 "실제로 그려진 카드 수" 기준

`GET /catalog`는 `category`/`name` 쿼리를 지원하지만 쓰지 않는다. 파라미터 없이 전체를 한 번 받고, 카테고리 칩·이름 검색·상단 카운트 뱃지를 전부 화면(`CollectionPage`)의 로컬 상태로 처리한다. 서버 재요청이 없어 타이핑마다 디바운싱이 필요 없고 결과가 즉각 반영된다.

뱃지 숫자는 서버가 준 `collectedCount`/`totalCount`를 쓰지 않고, `_inCategory()`로 걸러진 목록을 직접 세어(`scoped.where((e) => e.collected).length`) 계산한다. Repository가 미지 카테고리 항목을 목록에서 제외하기 때문에, 서버 숫자를 그대로 쓰면 뱃지가 "20/80"인데 카드는 79장만 보이는 불일치가 생길 수 있다. 로컬 카운트는 항상 실제로 그려진 카드 수와 정확히 같다.

#### 미수집 상세는 상세 API를 아예 부르지 않는다

서버는 미수집 항목의 상세를 필드 마스킹이 아니라 403으로 완전히 차단한다. `collection_detail_page.dart`는 목록에서 넘어온 `CatalogItemEntity.collected`로 먼저 분기해, 미수집이면 `catalogItemDetailProvider`를 아예 watch하지 않고 목록이 이미 아는 카테고리 색·아이콘만 그린 뒤 이름·설명 자리를 `?`로 채운다. 실패할 게 뻔한 요청을 보내고 403을 처리하는 대신 요청 자체를 만들지 않는 방식이다.

#### 게스트 모드에서 catalog API를 아예 호출하지 않는다

구현 초기에는 홈 진행률 카드·마이페이지 통계·도감 목록이 게스트 모드에서도 인증이 필요한 API를 그대로 호출해, 401 → 인터셉터가 "세션 만료"로 오인 → 로그인한 적 없는 게스트를 강제 로그아웃시키는 문제가 있었다(`07e6759`). `guestModeProvider` 원시 플래그를 기준으로 세 화면 모두 Provider를 아예 watch하지 않고 0/빈 목록을 직접 렌더하도록 고쳤다. `guestRestrictedProvider`는 `USE_MOCK_DATA=true`에서 false가 되어 토큰 없는 게스트의 401을 막지 못해 채택하지 않았다.

#### 수집일은 KST로 고정 변환

`catalog_repository_impl.dart`의 `_formatCollectedAt()`은 서버가 내려주는 ISO 8601 시각을 `toLocal()`이 아니라 `toUtc().add(Duration(hours: 9))`로 변환한다. 어대GO는 서울 어린이대공원 앱이라 수집 시각은 항상 KST 기준이어야 하는데, `toLocal()`을 쓰면 기기(또는 CI 러너)의 타임존에 따라 날짜가 하루 밀릴 수 있다(예: `2026-07-05T08:00:00+09:00`이 UTC 계열 환경에서 07.04로 보임). 이 경계 케이스는 `formats_collected_at_using_kst_even_when_utc_date_differs` 테스트로 고정했다.

#### 미지 카테고리는 조용히 제외, 로그는 응답당 1회

서버에 새 카테고리가 추가되면 구버전 앱은 색·아이콘이 없어 그릴 수 없는 값을 받는다. `DogamCategory.fromServer()`가 매칭 실패 시 기본값 대신 `null`을 반환하고, Repository는 해당 항목을 목록·요약에서 조용히 제외한다. 초기 구현은 제외된 항목마다 `debugPrint`를 찍어 응답 하나당 최대 50줄까지 로그가 쏟아질 수 있었는데, 이를 응답당 한 번(미지 카테고리 종류 + 제외 개수)으로 정리했다(`044a81f`). 상세 조회는 목록과 달리 항목이 하나뿐이라 미지 카테고리를 만나면 예외를 던져 반쯤 채워진 엔티티를 돌려주지 않는다.

#### 이미지 캐싱 — 설계 당시 가정(80종)과 실제(371종)의 괴리

설계 문서(`docs/superpowers/specs/2026-07-29-catalog-api-design.md` §8)는 `Image.network` 내장 위젯으로 충분하다고 결정했다 — 80종 규모 그리드에는 기본 메모리 캐시로 충분하고 새 패키지가 불필요하다는 판단이었다. 실제 카탈로그가 371개 항목으로 확인되면서 이 가정이 깨졌고, 이후 커밋(`86a3b43`)에서 `cached_network_image`로 교체해 디스크 캐시를 적용했다. `DogamCard`의 그리드 썸네일은 `memCacheWidth: 340`으로 디코딩 크기를 제한한다 — 3열 타일이 110dp 남짓이라 원본 해상도로 디코딩하면 보이는 차이 없이 메모리만 13배 쓰기 때문이다.

패키지 추가에 따라 iOS `Podfile.lock`과 macOS `GeneratedPluginRegistrant.swift`도 함께 갱신됐다(`fdc6e0d`, `b23eeb1`).

#### 도감 상세 히어로가 미수집을 카테고리 아이콘으로 그리던 버그

사진이 없을 때 쓰는 공용 폴백이 `collected` 여부를 몰라, 미수집 항목도 사진 로드 실패한 수집 항목과 똑같이 카테고리 아이콘을 그리고 있었다(spec §8은 미수집 히어로가 물음표여야 한다고 명시). `_Hero`에 `collected`를 넘겨 `?`(미수집)와 아이콘(수집인데 사진 없음/실패)을 가르도록 고쳤다(`b77b1c0`). 같은 커밋에서 로딩·에러 분기에 목록이 이미 들고 있는 `imageUrl`을 함께 넘겨, 상세를 다시 받는 동안 사진이 아이콘으로 잠깐 바뀌었다 되돌아오는 깜빡임도 없앴다.

#### 당겨서 새로고침 — 목록과 요약을 함께 무효화

셸이 탭 전환 시에도 `CollectionPage`를 살려두기 때문에 Provider가 스스로 사라지지 않고, 앱 실행당 한 번만 조회하면 새 서버 데이터를 받아올 방법이 없다. `_refresh()`는 `catalogItemsProvider`와 `catalogSummaryProvider`를 함께 invalidate한다 — 목록만 갱신하면 도감 뱃지 숫자와 홈 진행률 카드 숫자가 어긋나기 때문이다. 새로고침 인디케이터는 브랜드 `primary` 색으로 맞췄다(앱 전역에 `colorScheme`이 없어 기본값이 Material 보라로 나오는 문제, 아래 참고사항).

#### 퀴즈 보상 화면의 잠재 버그를 우연히 발견

`DogamCard`를 원시 필드 기반으로 바꾸는 리팩터 과정에서, 퀴즈 보상 화면(`quiz_reward_page.dart`)이 `collected: true`로 하드코딩돼 있어 `mockQuizItem.collected` 필드가 실제로는 아무 데도 쓰이지 않던(그래서 unused로 읽히던) 상태였음이 드러났다. 실제 필드값을 쓰도록 고쳤다(`52d3dfb`) — 이번 작업의 목표 범위는 아니었지만 리팩터 도중 드러난 회귀라 함께 수정했다.

### 📌 참고사항

- **도감 화면 실기기 확인은 백엔드 테스트 계정의 샘플 수집 이력이 있어야 가능하다.** 앱 안에서 수집이 늘어날 방법이 없으므로(수집 API 제외), 수집 이력이 비어 있으면 상세·수집일·진행률 게이지가 전부 미수집/0 상태로만 보인다
- CI가 `flutter test`를 돌리지 않으므로, 신규 테스트가 깨져도 PR 체크는 통과한다
- `main.dart`의 `ThemeData`에 `colorScheme`이 없어 기본 Material 위젯은 M3 보라색으로 렌더된다. 이번 작업에서 새로고침 인디케이터는 수동으로 `AppColors.primary`를 지정했지만, 앞으로 추가되는 기본 Material 위젯(다이얼로그, 스위치 등)은 하나씩 직접 스타일링하기 전까지 계속 보라색으로 보인다
- `cached_network_image`는 기본 설정으로 최대 200개 객체를 캐시하는데, 도감 항목은 371개다. 스크롤이 깊어지면 앞서 본 썸네일이 캐시에서 밀려나 재요청될 수 있다 — 현재는 문제로 드러나지 않았지만 실사용 데이터가 쌓이면 캐시 크기 조정이 필요할 수 있다
