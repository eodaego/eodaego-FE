# 현재 날씨 API 연동과 날씨 상세 화면 추가

### 📌 작업 개요
홈 상단 바의 목업 날씨(맑음 24도 고정)를 실제 서버 데이터로 교체하고, 바를 탭하면 진입하는 날씨 상세 화면 신규 추가. 날씨 feature에 data/domain/presentation 3계층 신규 구축.

**보고서 파일**: `.report/20260730_#20_날씨_API_연동과_상세_화면_추가.md`

### 🎯 구현 목표
- 현재 날씨 조회 API(`GET /api/1/weather/current`) 연동 — 기온, 습도, 풍속, 하늘 상태, 강수 형태
- 홈 상단 바를 날씨 전용으로 정리하고 실제 데이터로 교체 (혼잡도 뱃지 제거)
- 날씨 상세 화면 신규 추가 — 현재 상태 카드 + 날짜 단위로 끊은 시간대별 예보
- 서버가 모르는 하늘 상태/강수 형태를 내려도 앱이 깨지지 않도록 처리

### ✅ 구현 내용

#### 도메인 계층 — 날씨 enum과 KST 시각 처리
- **파일**: `lib/features/weather/domain/entities/weather_condition.dart`, `weather_entity.dart`
- **변경 내용**: 하늘 상태(`WeatherSky`)·강수 형태(`WeatherPrecipitation`) enum과 `WeatherEntity`/`HourlyForecastEntity` 추가. `parseKstDateTime()`·`nowKst()`로 KST 시각 처리 유틸 구현
- **이유**: 서버 예보 시각에 타임존 오프셋이 없어 기기 로컬 시각으로 해석되면 해외 시간대에서 예보 필터가 통째로 밀림. 모든 시각을 KST 벽시계 기준으로 고정해 비교 기준을 통일

#### 데이터 계층 — DTO·DataSource·Repository
- **파일**: `lib/features/weather/data/models/weather_model.dart`, `datasources/weather_remote_datasource.dart`, `repositories/weather_repository_impl.dart`
- **변경 내용**: Retrofit 기반 API 클라이언트와 freezed DTO 추가. Repository에서 DTO → Entity 변환, enum 매핑, 시각 파싱 수행
- **이유**: 프로젝트 Clean Architecture 규칙에 따라 서버 스키마와 화면 모델 분리. 에러는 `DioExceptionHandler.handle()`로 변환해 throw

#### 홈 상단 바 — 실데이터 교체
- **파일**: `lib/features/home/presentation/pages/home_page.dart`
- **변경 내용**: 목업 날씨를 `currentWeatherProvider` 데이터로 교체하고 `lib/core/mock/mock_park_status.dart` 삭제. 혼잡도 뱃지 제거. 바 전체를 탭 영역으로 만들어 날씨 상세로 이동
- **이유**: 혼잡도는 서버 API가 없어 목업 상태였음 — 실데이터 옆에 목업을 두면 바 전체의 신뢰가 깎이므로 범위에서 제외

#### 날씨 상세 화면 신규 추가
- **파일**: `lib/features/weather/presentation/pages/weather_detail_page.dart`, `lib/router/app_router.dart`, `route_paths.dart`
- **변경 내용**: `/weather` 라우트 추가. 현재 상태 카드(큰 아이콘, 라벨, 기온 원본값, 습도·바람, 관측 시각) + 지나간 시각을 걸러낸 시간대별 예보를 날짜 구분선(오늘/내일/날짜)으로 끊어 세로 목록 표시
- **이유**: 서버가 3.5일치 예보를 내려주는데 보여줄 화면이 없어 버려지고 있었음. 나들이 앱 특성상 방문 결정에 직접 쓰이는 정보

#### 날씨 아이콘 매핑
- **파일**: `lib/core/widgets/weather_icons.dart`
- **변경 내용**: 하늘 상태·강수 형태 → 아이콘 매핑 함수. 강수가 하늘 상태보다 우선 (비 오는데 해가 뜨면 안 됨). 홈과 상세 화면 두 feature가 함께 쓰므로 `core/widgets`에 배치
- **이유**: feature 간 직접 import 금지 규칙 — 처음 `features/weather` 아래 두었다가 홈에서도 쓰게 되면서 core로 이동

#### Provider 배선
- **파일**: `lib/features/weather/presentation/providers/weather_provider.dart`
- **변경 내용**: DataSource → Repository → `currentWeatherProvider` 3단 배선 (`@riverpod` 코드 생성 방식)
- **이유**: 홈 상단 바와 상세 화면이 같은 provider를 보므로 상세 진입 시 재요청이 나가지 않음

### 🔧 주요 변경사항 상세

#### KST 시각 파싱 — `parseKstDateTime()`
서버 시각 문자열(`2026-07-30T01:00:00`)에 `Z`를 붙여 UTC로 파싱하면 필드값이 그대로 KST 벽시계가 됨. 서버가 오프셋(`Z`, `+09:00`)을 붙여 보내는 경우도 `isUtc` 확인 후 +9시간으로 처리. 그 외 형식이 깨진 값은 기기 로컬로 조용히 잘못 해석되는 대신 null 반환 — 해당 예보 슬롯은 목록에서 제외하고 개수만 로그로 남김.

**특이사항**:
- `nowKst()`는 `clock.now()`를 사용 — 테스트에서 `withClock`으로 시각을 고정하면 프로덕션 코드도 같은 순간을 봄. 프로덕션에서는 `DateTime.now()`와 동일

#### 알 수 없는 서버 값 방어
실제 응답에서 확인된 값은 하늘 상태 `맑음`·`구름많음`, 강수 형태 `없음`뿐. 나머지(`흐림`, `비`, `눈` 등)는 기상청 SKY/PTY 코드 표준 표기를 따른 추정. 매핑에 없는 값이 오면 enum은 null, 아이콘은 물음표로 떨어지고 라벨은 서버 원문을 그대로 표시 — 화면이 비거나 깨지지 않음.

#### 게스트 모드 가드
게스트는 토큰이 없어 API를 부르면 401 → 인터셉터가 세션 만료로 오인해 강제 로그아웃 (도감 요약에서 겪은 버그와 동일 패턴). 게스트 모드에서는 날씨 바 자체를 렌더링하지 않아 요청을 원천 차단.

#### 상태별 UI 처리
- 홈 바: 로딩은 스켈레톤, 실패는 바 안에서만 조용히 알림 (홈에는 다른 콘텐츠가 있으므로)
- 상세 화면: 로딩은 카드+목록 스켈레톤, 실패는 전체 화면 + '다시 시도' 버튼 (이 화면이 전부이므로)
- 남은 예보가 없으면 현재 날씨는 유지하고 예보 자리에만 안내 문구 표시

#### 기온 표시 기준
홈 바는 반올림 정수(`24°`), 상세 화면은 원본값(`24.3°`) 표시. 응답의 현재 기온과 시간대별 기온은 출처가 달라 값이 다를 수 있어 현재 카드에 관측 시각(`15시 기준`)을 함께 표시.

### 📦 의존성 변경
- 없음 (기존 `clock` 패키지 활용)

### 🧪 테스트 및 검증
신규 테스트 6개 파일:
- `weather_condition_test.dart` — enum 변환, 알 수 없는 값 null 처리
- `weather_entity_test.dart` — KST 파싱(오프셋 유무·깨진 형식), 지나간 예보 필터, 조건 라벨
- `weather_repository_impl_test.dart` — DTO → Entity 변환, 읽을 수 없는 시각 슬롯 제외, 에러 변환
- `weather_icons_test.dart` — 모든 강수 종류·하늘 상태 아이콘 매핑, 강수 우선 규칙
- `home_page_weather_bar_test.dart` — 게스트 가드, 로딩/에러/데이터 상태 회귀, 라벨 오버플로 방지
- `weather_detail_page_test.dart` — 날짜 구분선 그룹핑, 빈 예보 안내, 재시도 동작

시간 의존 테스트는 `withClock`으로 시각을 고정해 실제 시계와 무관하게 검증. 오늘 날짜 경계 근처에서 흔들리지 않도록 슬롯 오프셋을 20초·30초로 좁혀 안정화.

### 📌 참고사항
- 서버 하늘 상태·강수 형태의 미확인 표기(`흐림`, `비` 등)는 추정값 — 실제 표기를 백엔드에 확인 필요
- 날씨 조회는 로그인이 필요한 API — 공개 정보임에도 인증을 요구하는 부분은 백엔드와 별도 논의
- 공원 혼잡도는 서버 API가 준비되면 별도 이슈로 진행
- 습도·풍속은 상세 화면에만 노출 (홈에는 미노출, 이슈 범위 정의대로)
