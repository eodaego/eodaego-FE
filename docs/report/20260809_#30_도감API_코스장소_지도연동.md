### 📌 작업 개요
지도 코스 마커 탭 시 장소별 도감 수집 여부를 보여주는 기능 구현. 백엔드가 아직 `facilityId`↔`externalId` 연결 식별자를 노출하지 않아, 이름 완전 일치 + 카테고리 필터 조합으로 임시 연결 배선을 완료. 같은 브랜치에 Google Maps 실지도 전환 후속 정리(장소 카드, 코스 시트 목록 ↔ 지도 마커 상호 연동), 앱 전역 하드코딩 문자열(에셋 경로·메시지 키·간격 값)의 상수화, 홈 화면 레이아웃 개편, 코스 추천 결과 화면 뒤로가기 정책 변경이 함께 포함됨.

### 🎯 구현 목표
`.issues/20260809_기능개선_도감API_코스장소_연결_식별자.md` 기준:
- 지도 코스 장소 탭 시 도감 수집 여부를 카드로 노출
- 도감 목록 조회의 이름 부분 일치로 인한 오연결(예: "동물나라" 검색 시 "동물나라 사육장"까지 포함) 방지
- 정확한 식별자(`facilityId`/`externalId`)가 백엔드에 아직 없으므로, 이름 완전 일치 + 카테고리 필터로 임시 조인해두고 식별자가 추가되면 조인 기준만 교체 가능하도록 구조화
- (추가) 코스 시트의 장소 목록과 지도 마커를 양방향으로 연동 — 마커가 겹쳐 안 보이는 장소도 목록 탭으로 열 수 있게 함
- (추가) 화면 전반에 흩어진 하드코딩 문자열 리터럴(에셋 경로, 메시지 키, `SizedBox`/`padding` 매직 넘버)을 상수 클래스로 정리

### ✅ 구현 내용

#### 도감 목록 API에 category/name 쿼리 파라미터 추가
- **파일**: `lib/features/collection/data/datasources/catalog_remote_datasource.dart`, `catalog_remote_datasource.g.dart`, `catalog_mock_datasource.dart`
- **변경 내용**: `getCatalog()`가 인자 없는 전체 조회만 지원하던 것을, `getCatalog({category, name})`로 확장. `name`은 서버 부분 일치 검색이며, 미수집 항목은 응답의 `name`/`imageUrl`이 null로 내려온다는 제약을 문서화. mock 데이터소스도 동일 규칙(부분 일치 `contains`)으로 맞춤.
- **이유**: 지도 마커 카드가 장소 하나만 짚어 조회해야 하는데, 기존에는 전체 목록만 받아올 수 있었음. 코드 생성 파일(`.g.dart`)도 함께 갱신됨.

#### Repository/Domain 계층에 name 인자 배선
- **파일**: `lib/features/collection/data/repositories/catalog_repository_impl.dart`, `lib/features/collection/domain/repositories/catalog_repository.dart`
- **변경 내용**: `getCatalogItems({category, name})`으로 시그니처 확장. `getCatalogItems()`(인자 없음)는 도감 화면 전체 조회용으로 유지, 인자를 쓰는 경로는 "한 항목만 짚어야 하는" 지도 마커 카드 전용임을 문서화.
- **이유**: Presentation 계층(지도)에서 필터 조회가 가능하도록 Domain 인터페이스 확장.

#### 장소별 도감 상태 판정 Provider 신설
- **파일**: `lib/features/map/presentation/providers/place_catalog_provider.dart` (신규), `place_catalog_provider.g.dart` (신규)
- **변경 내용**: `placeCatalogStatusProvider(placeName, category)`가 이름+카테고리로 도감을 조회하고, 결과 중 `collected == true && name == placeName`(완전 일치)인 항목만 "수집함"으로 판정. 세 가지 상태를 `({CatalogItemEntity? collected, bool inCatalog})` 튜플로 표현(수집함 / 도감에 있으나 미수집 / 도감에 없는 시설).
- **이유**: 서버 이름 검색이 부분 일치라 오탐 가능성이 있어, 카테고리로 1차 좁히고 이름 완전 일치로 2차 검증. 정확한 식별자가 없는 현재 제약 하의 최선책.

#### 장소 정보 카드 위젯 신설
- **파일**: `lib/features/map/presentation/widgets/place_info_card.dart` (신규)
- **변경 내용**: 지도 마커 탭 시 뜨는 카드. 도감 상태에 따라 3가지 UI(수집함 → 실사 이미지+도감코드+"도감에서 보기" 버튼 / 미수집이지만 도감에 있음 → "여기서 찍기" CTA / 도감에 없는 시설 → 안내 문구만)를 분기. 네이티브 `InfoWindow`를 대체(스타일 커스텀 불가, 약도 모드에서 미지원 문제 해결).
- **이유**: 이슈의 핵심 요구사항 — 지도에서 장소별 도감 수집 여부 확인.

#### 지도 위젯에 장소 탭 콜백 연결
- **파일**: `lib/features/map/presentation/pages/map_page.dart`, `lib/features/map/presentation/widgets/park_google_map.dart`, `lib/features/map/presentation/widgets/park_schematic_map.dart`
- **변경 내용**: `ParkGoogleMap`/`ParkSchematicMap`에 `onPlaceTap` 콜백 추가, 지도 페이지가 탭된 장소를 상태로 들고 `PlaceInfoCard`를 오버레이. 코스가 바뀌면 카드가 자동으로 닫히도록 처리. 카드 위치를 지도 하단에서 상단으로 이동(좌하단 Google 로고·우하단 내 위치 버튼·하단 코스 시트와 겹치지 않도록), 카드 리마운트를 `KeyedSubtree`로 감싸 장소가 바뀔 때 도감 조회가 새로 돌게 함.
- **이유**: 마커 탭 → 카드 표시 흐름 배선.

#### 코스 시트 장소 목록 ↔ 지도 마커 상호 연동
- **파일**: `lib/features/map/presentation/widgets/course_sheet.dart`, `lib/features/map/presentation/widgets/map_marker.dart`, `lib/features/map/presentation/pages/map_page.dart`, `lib/features/map/presentation/widgets/place_info_card.dart`
- **변경 내용**: `CourseSheet`에 `onPlaceTap`/`selectedPlaceName` 파라미터 추가. 장소 목록을 `Row` 나열에서 탭 가능한 `_PlaceRow`(`Material`+`InkWell`)로 교체, 선택된 줄은 카테고리 `dark` 색 + `tint` 배경으로 표시. 목록 번호는 인덱스가 아닌 서버 `visitOrder`를 사용(지도 마커와 순서가 어긋나지 않도록). `MapMarker`에 `elevated` 플래그 추가 — 지도 위에 뜬 마커만 그림자를 켜고, 목록·카드 안에서는 끔. `map_page.dart`가 시트의 `onPlaceTap`과 지도의 `onPlaceTap`을 같은 `_openPlace` 핸들러로 묶고, `selectedPlaceName`을 양쪽에 내려 시트 목록과 지도가 같은 선택 상태를 공유. `place_info_card.dart`는 도감에 없는(코스 전용) 장소일 때 별도 큰 안내 박스 대신 이름 아래 한 줄("구경하고 가는 곳이에요")로 축약.
- **이유**: 실제 공원 지도는 시설이 밀집해 마커가 겹치는 경우가 많아, 겹친 장소는 시트 목록 탭이 유일한 진입 경로가 되어야 함. 도감에 없는 시설 안내 문구도 "코스에만 있는 장소예요"(내부 사정 노출)에서 사용자가 할 수 있는 행동 중심 문구로 교체.

#### 하드코딩 리터럴 상수화 (에셋 경로 / 메시지 키 / 간격)
- **파일**: `lib/core/constants/app_assets.dart`(신규), `lib/core/constants/app_message_keys.dart`(신규) + 소비처 약 30개 파일(`auth`/`quiz`/`weather`/`scan`/`user`/`collection`/`course` 각 페이지·리포지토리, `core/widgets` 하위 등)
- **변경 내용**: 약관 JSON 경로(`'assets/legals/...'`)와 마스코트 이미지 경로를 `AppAssets`로, 리포지토리의 `messageKey: '...'` 문자열 리터럴(에러/성공 메시지 식별자)을 `AppMessageKeys`로 각각 상수화하고 전 사용처를 치환. 함께 다수 파일에서 `SizedBox(height: 12.h)` 류 매직 넘버를 기존 `AppSpacing` 토큰(`AppSpacing.sm/md/base/lg/xl`)으로 치환.
- **이유**: 문자열 리터럴 오타가 컴파일 타임에 잡히지 않고, 같은 값이 여러 파일에 흩어져 있어 변경 시 누락 위험이 있었음. 상수화로 오타 방지 및 단일 출처 확보. 로직 변경 없는 기계적 리팩터.

### 📌 참고사항
- 백엔드가 `facilityId`/`externalId` 동일성을 회신하고 식별자를 노출하면, `placeCatalogStatusProvider`의 이름 매칭 로직(카테고리+이름 완전 일치)을 식별자 매칭으로 교체하는 후속 작업이 필요함(이슈 본문에 명시된 계획).

- `AppAssets`에는 아직 `today.png`, `map_v6.jpg` 등 이번 브랜치에서 추가/수정된 다른 에셋 경로는 포함되지 않음 — 필요 시 후속으로 편입 검토.
