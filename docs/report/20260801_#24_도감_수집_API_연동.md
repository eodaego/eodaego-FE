# 도감 수집 API 연동 (POST /catalog/{catalogItemId}/collect)

### 📌 작업 개요

퀴즈를 맞혀도 도감에 반영되지 않던 문제 해결. 서버 수집 API를 연동하고, 퀴즈 보상 화면 진입 시 해당 항목을 자동 수집하도록 연결.

#18(도감 목록·상세·요약 연동)에서 조회만 붙였던 도감 기능에 쓰기 경로를 추가한 작업.

### 🎯 구현 목표

- 도감 수집 API 연동 (204 No Content)
- 퀴즈 보상 화면 진입 시 자동 수집
- 이미 수집한 항목 중복 호출 방지
- 수집 후 도감 목록·요약 즉시 갱신
- 게스트는 호출 자체를 하지 않도록 차단

### ✅ 구현 내용

#### 데이터 계층 배선

- **파일**: `api_endpoints.dart`, `catalog_remote_datasource.dart`, `catalog_repository.dart`, `catalog_repository_impl.dart`
- **변경 내용**: `POST /api/1/catalog/{catalogItemId}/collect` 엔드포인트 추가, Retrofit 메서드와 Repository 메서드 연결
- **이유**: 응답 본문이 없는 204라 반환 타입을 `Future<void>`로 두고, 에러는 `DioExceptionHandler`가 변환

#### code 기반 수집 Provider 추가

- **파일**: `catalog_provider.dart`
- **변경 내용**: `collectCatalogItemByCode(code)` provider 추가 — 도감 목록에서 code로 항목을 찾아 id로 수집 요청
- **이유**: 퀴즈 문항은 도감 항목 **id를 모르고 code(`A001` 등)만 안다.** 호출부가 id를 알아낼 방법이 없어 provider가 code → id 변환을 책임

#### 퀴즈 보상 화면 연동

- **파일**: `quiz_reward_page.dart`
- **변경 내용**: 보상 화면 진입 시 문항 code로 수집 발화. 게스트는 제외
- **이유**: 정답을 맞힌 시점이 아니라 보상 화면 진입 시점이 "획득 확정" 지점

#### 목 데이터 대응

- **파일**: `catalog_mock_datasource.dart`
- **변경 내용**: `collectCatalogItem()`을 no-op으로 구현
- **이유**: 인터페이스 충족용. 퀴즈 문항 6개(A001~A003, P001~P003)가 목 데이터에서 전부 이미 수집 상태라 provider의 로컬 pre-check에서 걸러져 실제로 호출되지 않음

### 🔧 주요 변경사항 상세

#### collectCatalogItemByCode

동작 순서: 도감 목록 조회 → code로 항목 검색 → 미수집이면 수집 요청 → 목록·요약 무효화

```
code 못 찾음  → 경고 로그 후 조용히 종료
이미 수집(로컬) → 요청 없이 종료
수집 성공      → catalogSummary/catalogItems invalidate
409            → 성공으로 취급하고 동일하게 갱신
그 외 에러      → AsyncError로 남김
```

**특이사항**:
- **`ref.read`로 목록을 읽는다.** `watch`를 쓰면 아래 `invalidate`가 이 provider를 다시 돌려 무한 루프가 된다
- **로컬 pre-check + 서버 409 처리 이중 방어.** 로컬 목록이 최신이 아닐 수 있어 서버가 `CATALOG_ITEM_ALREADY_COLLECTED`를 주면 그것도 성공으로 취급
- 409 외의 `ServerException`은 rethrow. 수집은 부가 흐름이라 화면이 error 상태를 그리지는 않지만, 에러를 삼키지는 않음

#### 게스트 가드

게스트는 수집 발화와 진행률 조회 **둘 다** 차단.

**특이사항**:
- 게스트는 토큰이 없어 401이 나고, **인증 인터셉터가 이를 "세션 만료"로 오인해 로그인한 적 없는 사용자를 강제 로그아웃시킨다.** 이전에 커밋 `56e947b`에서 이미 겪었던 버그
- 가드를 provider 안이 아니라 **호출부(퀴즈 보상 화면)에 둔다.** provider는 게스트 여부를 모르고, 호출부가 이미 `guestModeProvider`를 보고 있음
- 진행률 줄(`_CollectionProgress`)은 게스트일 때 위젯 자체를 빌드하지 않아 내부 watch도 실행되지 않음

#### 문항 code가 null인 경우

`question.code`가 null이면 수집을 발화하지 않음. 도감과 연결되지 않은 문항을 대비한 방어.

### 📌 참고사항

- 수집은 **부가 흐름**이다. 실패해도 퀴즈 보상 화면 자체는 정상 동작하며 에러 UI를 띄우지 않는다
- 목 모드(`USE_MOCK_DATA=true`)에서는 퀴즈 문항 6개가 이미 수집 상태라 수집 동작을 체감할 수 없다. 실제 검증은 실 API 모드에서 해야 한다
- 수집 시점을 정답 직후가 아닌 보상 화면 진입으로 잡았으므로, 향후 보상 화면을 건너뛰는 흐름이 생기면 수집 발화 지점을 함께 옮겨야 한다
