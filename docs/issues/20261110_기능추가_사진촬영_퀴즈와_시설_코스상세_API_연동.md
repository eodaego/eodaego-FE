📝 현재 문제점
---

- 촬영 화면(`lib/features/scan/presentation/pages/scan_page.dart`)에 카메라가 없다. 셔터를 누르면 사진 없이 퀴즈 화면으로 넘어가기만 한다.
- 퀴즈(`lib/features/quiz/`)는 앱에 들어 있는 예시 문항(`assets/mock/quiz.json`)을 순서대로 돌려서 낸다. 무엇을 찍든 같은 문항이 나오고, 정답을 맞혀도 도감 수집이 서버에 기록되지 않는다.
- 백엔드에 사진 인식 퀴즈 API가 머지됐다(BE #39, 2026-11-09). 앱은 아직 이 API를 부르지 않는다.
  - `POST /api/1/quiz`: 사진과 대상 종류(동물/식물/장소)를 보내면 3지선다 퀴즈를 만든다
  - `POST /api/1/quiz/{quizId}/answer`: 답을 제출하고, 정답이면 서버가 도감 수집까지 처리한다
- 서버는 촬영 전에 대상 종류를 꼭 받아야 하는데, 지금 촬영 화면은 종류 구분 없이 자동 인식하는 기획으로 그려져 있다.
- 지도는 고른 코스의 장소만 그린다. 코스를 고르지 않으면 출입문 말고는 비어 있다. 서버의 시설 조회 API(`GET /api/1/facilities`, `GET /api/1/facilities/{facilityId}`)는 있지만 앱이 쓰지 않는다.
- 코스 상세 조회 API(`GET /api/1/courses/{courseId}`)도 앱에서 부르지 않는다. 그래서 지도에 띄운 코스의 수집 여부는 추천받은 시점 그대로라, 앱이 직접 뒤집어 맞추고 있다.
- 앱의 API 명세 사본(`docs/api-docs.json`)에 퀴즈 API가 빠져 있다.

🛠️ 해결 방안 / 제안 기능
---

- 촬영 화면에서 실제 카메라로 사진을 찍는다. 지금의 어두운 화면, 촬영 프레임, 셔터 디자인은 그대로 둔다.
- 셔터 위에 동물, 식물, 장소 칩 3개를 둔다. 처음엔 동물이 골라져 있고, 바꾸면 프레임과 셔터 색, 안내 문구가 그 종류에 맞게 바뀐다. 도감 화면 필터와 같은 칩을 쓴다(시안 A안으로 결정).

![촬영 화면 카테고리 칩 시안 A안](https://github.com/eodaego/eodaego-FE/releases/download/qa-evidence/issue_20261110-004328_scan-chip-a.png)

- 찍은 사진과 고른 종류로 퀴즈를 받아 3지선다를 보여준다. 오답이면 그 보기만 막고 다시 고르게 하고, 정답이면 보상 화면으로 넘어간다.
- 인식에 실패하면 종류를 바꿔 다시 찍어보라고 안내한다. 사진 형식 문제, 용량 초과, 서버 응답 없음도 각각 알아들을 수 있는 문구로 안내한다.
- 카메라 권한을 거절했을 때 안내와 설정 이동 경로를 둔다.
- 로그인하지 않은 상태에서 셔터를 누르면 지금처럼 로그인 안내를 띄운다.
- 예시 데이터 모드에서는 지금의 예시 문항으로 계속 동작하게 한다.
- 지도에 공원 시설 전체를 시설 조회 API로 보여준다. 좌표가 없는 시설은 마커를 그리지 않는다. 코스를 고르면 나머지 시설은 흐리게 남긴다(시안 A안으로 결정).
- 지도 장소 카드에 시설 소개와 운영시간을 보여준다.
- 지도에 코스를 띄울 때와 퀴즈로 도감을 모은 뒤, 코스 상세 조회 API로 그 코스를 다시 받아 '모음/아직' 표시를 서버 기준으로 맞춘다.
- 약도 위치와 출입문 좌표는 앱의 기존 데이터를 그대로 쓴다(서버에 약도 좌표가 없고, 출입문 구분 값이 응답에 없음).
- `docs/api-docs.json`을 최신 서버 명세로 갱신한다.
